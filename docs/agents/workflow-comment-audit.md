# workflow-comment-audit：注释与文档事后审计

> 单元定义：对已编写代码的注释与文档做事后检查。注释纪律、文档规范本应在编写之初遵守，本工作流用于检查已写代码是否符合，发现问题再修正。目标：注释收敛到 AGENTS 规范线内，重要信息以文档形态留存、零丢失。

## 触发

- 审查既有代码的注释（"审查注释 / 去掉没用的 / 精简"）
- 组件文档缺失或与代码不符，需要补齐/修订

范围以用户指派为准。

## 步骤

### P1 规范就位

读 AGENTS 及本单元涉及的领域规范文档（如 `docs/agents/` 的 standards-*、CONTEXT.md、相关 ADR），确认注释与文档的规范所在。规范内容不在此重复——AGENTS 是单源真相，本单元只引用它。

**完成标准**：能指出本组件注释/文档的规范依据在哪（哪份文档定义了"注释线内"、文档格式）。

### P2 理解组件：先文档，后代码

1. **先读文档**：契约行为——API、属性、信号、语义边界。文档给"应该是什么"。
2. **后读代码**：实现原理——内部机制、算法、非显然行为。代码给"实际是什么"。

若组件无文档：跳过"先读文档"，将"无文档"记为差异清单中的"缺失"项，直接从代码提取实际行为作为对照基准。

顺序的意义：两者对照才能发现差异（文档缺失、过时、或与实际不符）。直接读代码会丢失"文档声称 vs 实际实现"的对照视角。

**完成标准**：能同时说出文档声称的契约与代码实际的行为，并列出差异清单（缺失 / 过时 / 一致）。

### P3 审计与修正：删 / 补 / 重定位

对照 AGENTS 规范检查 P2 的信息，发现问题并修正：

- **冗余** → 删（惯例类、AGENTS 已覆盖的、重复文档的、与实现不符的注释——后者的信息若已由文档承载则直接删，否则修订为符合实现）
- **缺失** → 补（组件无文档则新建，文档过时则修订）
- **重要但量大** → 从注释重定位为文档/文章形态

处置是**重新表达而非搬运**：意思准确、表达流畅，与既有文档/注释风格一致。

**完成标准**：注释收敛到 AGENTS 规范线内；原注释承载的重要信息都能在文档中读到；留下的注释只解释读代码看不懂的。

### P4 验证

- 走读检查注释清理结果，确认未误删代码结构（import / 宏 / 绑定等；本单元改动按 AGENTS 约定不运行测试）
- 文档链接可解析、`docs/reference/` 各模块 index.md 注册完整无重复
- 契约描述与代码实现一致（P2 差异清单清零）

**完成标准**：以上全过，单元结束。

## 边界

本单元只做注释与文档的事后审计修正，不扩展为组件审计、重构或测试改造。
